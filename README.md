# hana-kb

Hana 的本地知识库插件。把文件丢进库，对话中自然提问，相关内容被找出并附带来源出处。数据留在本机，检索链路全部透明可溯。

受 Cherry Studio 知识库启发，但在纯向量之外加入了实体关系图谱：向量负责"意思像不像"，图谱负责"谁和谁连着"，两条路各取所长。

设计哲学：知识库的职责是把带出处、带置信度、带结构上下文的好原料交给 AI；消化、推理与表述是 AI 的事。本插件不为追求“直接给人看的完美答案”而过度加工，而把力气花在原料的完整性、可溯性和诚实性上。

## 特性

中文结构感知分块：制度文档按标题/条款链（第X章 > 一、 >（一）> 1. >（1）> 多级数字编号）识别语义边界，条款不再从中间截断；续块自带标题路径锚点；长表格续块前置表头。

**检索**

- 向量检索（语义指纹，支持任意措辞）
- 可选 BM25 关键词融合（精确术语、编号类查询）
- 可选图谱追加（沿实体关系链召回关联片段，只追加不重排，不干扰主排序）
- 可选多样性重排（多主题问题让更多文档进入结果；开关旁自动提示是否建议开启）
- 每个结果带完整出处：文档名、标题路径、原文偏移量
- 检索置信提示：结果相关性过低时主动提醒 Agent 如实说明，不编造答案

**图谱**

- LLM 抽取实体与关系，构建每个库自己的关系网络
- 全景视图：力导向布局，Louvain 社区检测自动着色知识聚类，节点按连接数分级、连线粗细反映关系强度，悬停高亮邻居，拖动整理、滚轮缩放、双击复位
- 连线视角：点击任一节点进入它的一跳关系，顺着关系链可连续跳转
- 图质量体检：实体数、连线数、平均度、孤立率、未覆盖片段

**管理**

- 多知识库并存，每库一个独立 SQLite 文件，可备份、可搬走
- 支持格式：Markdown、txt、docx、doc、xlsx、xls、pptx、ppt、epub、rtf、odt（Office 文档统一转为 Markdown 后入库，表格/标题结构保留）
- 网页入库：给链接即抓取正文转 Markdown，来源链接记录在文档头部可溯源。三级引擎自动降级：静态抓取（快）→ 本机 Chrome/Edge 渲染（覆盖公众号等 JS 渲染页）→ crawl4ai 服务（可选）
- 单文件入库前可预览转换结果；文件列表随时查看每个文件的入库内容
- 文件/文件夹入库，断点续跑，同内容跳过，内容变更自动重入
- 界面管理四视图：库列表、文件管理、召回测试、图谱浏览
- 每个库独立参数：topK、相似度阈值、分段大小、图谱/BM25/多样性开关

**对话**

- 13 个 Agent 工具：建库、入库、网页入库、检索、图谱构建、参数调整，对话中可直接调用

## 安装

**方式一：Release 安装包（推荐）**

1. 从 [Releases](../../releases/latest) 下载最新版 zip
2. Hana 设置 → 插件 → 本地安装，选择该 zip
3. 启用插件

**方式二：源码构建**

```bash
git clone https://github.com/a13188087907/hana-kb.git
cd hana-kb
npm install
```

将目录打包为 zip 后本地安装。

## 快速开始

1. 打开插件页 → 左侧「全局设置」，填写 embedding 服务
   - 推荐：硅基流动 `BAAI/bge-m3`
   - 想数据不出本机：本地 Ollama（网络白名单已包含 127.0.0.1）
2. 若要使用图谱，同界面填写 LLM 配置
   - 推荐：DeepSeek 官方 `deepseek-v4-flash`（Base URL 为 `https://api.deepseek.com/v1`，实测验证）
   - 备选：硅基流动 `deepseek-ai/DeepSeek-V4-Flash`（与 embedding 同渠道同 key）
3. 新建知识库 → 添加数据源（文件或文件夹）
4. 文件 tab 查看入库状态，召回测试里试试你的问题
5. 在 Hana 对话中直接说"搜一下 XX 库里的 XX"，Agent 会调用检索工具
6. 添加网页：库页面「添加数据源 → 添加网页」，粘贴链接即可（公众号等 JS 渲染页自动调用本机 Chrome/Edge）

## 检索原理

```
问题
 ├─ 向量路：语义相似召回（topK×3 候选）
 ├─ [可选] 多样性重排：同文档后续片段折价，给其他文档让位
 ├─ [可选] BM25 路：关键词召回
 └─ 两路 RRF 融合 → topK 主排序
[图谱开启时] 实体名匹配 → 关系一跳扩展 → 追加到主排序末尾（最多 5 条）
```

关键设计全部经过对照实验验证（跨三套语料 46 题）：

- 图谱只追加不重排：主排序不受图谱噪声影响
- 多样性重排采用"文档级折扣 + 80% 触发保护"：多文档问题覆盖率提升，单文档问题零损伤
- 默认相似度阈值 0.3（相似度口径），过严会静默砍掉正常命中

## 参数说明

| 参数 | 默认 | 说明 |
|---|---|---|
| topK | 15 | 返回片段数；多样性重排建议在 ≤10 时开启 |
| 相似度阈值 | 0.3 | 向量路的入场门槛（相似度口径） |
| 分段大小 | 400 | 修改后需重建索引生效 |
| 重叠 | 50 | 同上 |
| 图谱 | 关 | 开启后构建需调用 LLM |
| BM25 | 关 | 收益验证未完成，开启前建议实测 |
| 多样性重排 | 关 | 开关旁自动提示是否建议开启 |

## 数据与隐私

- 文档文本会发送给你配置的 embedding/LLM 服务商（用于计算语义指纹与抽取关系）
- API 密钥仅保存在本机插件数据目录，不随插件分发
- 敏感路径防护：凭据类文件（.env、密钥、.ssh 等）会被拒绝入库
- 网页抓取拦截内网与本机地址（SSRF 防护）

## 已知边界

- pdf 未支持（中文 pdf 纯文本提取乱码风险，需专项验证后开放）
- 网页入库覆盖静态网页与 JS 渲染页（实测：公众号、博客、文档站、X 帖子、B 站动态）；极少数需登录或强反爬的页面会诚实报错
- 枚举型跨文档查询（“哪些制度规定了 X”）建议开启 BM25 融合，精确词匹配是这类查询的主场
- 费用熔断未实现：大批量入库前请留意 API 用量
- 图谱构建成本参考：千段规模约数元、十几分钟，后台执行

## 开发

```bash
npm test          # 单元测试 + DOM 渲染断言
npm run selftest   # 真实 API 全链路自测
```

架构约束（均有实验依据，勿回退）：

- 向量存储用普通 BLOB 列 + `vec_distance_cosine`，不使用 vec0 虚拟表（删除/更新性能）
- 实体归并只用名称归一化 + 别名交叉，禁止两两向量比较（实测 O(n²) 跑不完）
- 图谱路只追加不重排；多样性重排的 α 与触发线有数据支撑
